## Структура проекта

```
client/                 всё, что отдаётся в браузер
  index.html            разметка меню и HUD
  css/style.css         стили интерфейса
  vendor/               Three.js (локальная копия, интернет не нужен)
  js/main.js            точка входа: игровой цикл
  js/core/              утилиты, настройки, общее состояние (state.js)
  js/render/            рендерер и камера, текстуры, стили уровней, освещение
  js/world/             геометрия уровня, интерактивные объекты, мебель и декор
  js/entities/          модели игроков и существ
  js/audio/             процедурный звук
  js/net/               соединение с сервером и обработка сообщений
  js/ui/                HUD, меню, миникарта
  js/game/              управление игроком, ввод, взаимодействие (E)
server/
  index.js              точка входа: HTTP + WebSocket, запуск цикла
  config.js             порт, частота тика, отладочные переменные
  http.js               раздача client/ и shared/
  ws.js, clients.js     WebSocket без зависимостей, список игроков, рассылка
  game.js               уровни, тик мира, сообщения игроков
  level.js              сборка уровня: карта, объекты, существа (без сети — используется и тестами)
  puzzles/              головоломки (описаны хуками): util.js — переключатели, шлюзы, вода, сирена;
                        classic.js, pools.js, parking.js, tunnels.js, hospital.js, offices.js — по уровням
  mobs.js               ИИ существ: таблица чувств (зрение, слух, конус, тепло) и особые типы
  director.js           «режиссёр» напряжения и сложности
  records.js            таблица рекордов (data/records.json, отдаётся по /records.json)
  skinstealer.js        двойник
  admin.js              админ-панель хоста
shared/                 общий для клиента и сервера код (браузер грузит его обычными <script>)
  core.js               константы, типы клеток, PRNG, хэш
  world.js              колонки высот, физика тела, граф навигации, видимость
  gen2d.js              планировки одного этажа (лабиринт, залы, комнаты, коридор-змейка)
  build.js              связи этажей: лестницы, стремянки, провалы, атриумы, бассейны, лазы; «ремонт» карты
  levels/*.js           собственные генераторы уровней: знаковые места, шлюзы, выход, шаги для проверки
  map.js                список уровней кампании, generate(seed, уровень), расстановка точек
tests/                  автотесты
```

Клиент — ES-модули без сборки: браузер грузит их напрямую. `three` подключается через import map в `index.html`.

## Схема уровня

Уровень — это `F` этажей сетки 45×45 клеток по 4 м; этаж `f` начинается на высоте `f·FH`.
Каждая клетка этажа имеет тип (`BR.T`):

| Тип | Что это |
|---|---|
| `FLOOR` | пол |
| `WALL` | стена на всю высоту этажа |
| `HOLE` | провала пол: видно этаж ниже, можно упасть |
| `STAIR` | лестница: 2 клетки = подъём на этаж; `aux` = направление подъёма + номер сегмента |
| `LADDER` | вертикальная лестница у стены (`aux` — сторона стены); над ней на этаже выше — `HOLE` |
| `POOL` | чаша бассейна, `aux` — глубина в четвертях метра |
| `VENT` | вентиляционный лаз высотой 1,15 м (только ползком, существа не пролезают) |
| `LOW` | низкий потолок 2,35 м |
| `BLOCK` | низкое препятствие 1,3 м (машина, стол, кровать, стойка): поверх видно, пройти нельзя; `aux` — модель |

Вода задаётся зонами: `map.wz[клетка]` — номер зоны, `map.wl[зона]` — высота поверхности (сервер может её менять).
Из типов клеток строятся «колонки» твёрдых интервалов по высоте; по ним работают физика, видимость, рендер.
Граф навигации (`buildNav`) — узлы «этаж × клетка», рёбра: шаг, подъём по лестнице, падение в провал (только вниз), стремянка, лаз, вода.

Уровень описывается в `LEVELS` (`shared/map.js`):

```js
{
  name: 'Мой уровень', style: 'yellow', F: 2, FH: 3.4, spawnF: 1, exitF: 0,
  floors: [{ gen: 'maze', p: {...} }, { gen: 'rooms', p: {...} }],   // планировка каждого этажа
  build(map, rnd, used) {                                             // вертикаль и особенности
    BR.addStairs(map, rnd, 0, 3, used);  BR.addHoles(map, rnd, 1, 5, 2);
    BR.addPools(map, rnd, 0, 2, { depth: 2.5 });  BR.addVents(map, rnd, 0, 6);
  },
  mobs: 1, mobType: 'stalker', mobSpeed: 1, water: 3, puzzles: ['fuses'], fuses: 3, intro: '…',
}
```

После `build` функция `finalize` «ремонтирует» карту: соединяет изолированные зоны, ставит аварийные лестницы,
закрывает провалы-ловушки и заделывает недостижимое. Поэтому из любой точки, куда можно попасть, можно вернуться к старту.
`npm run verify` проверяет это на 300 seed для каждого уровня.

## Как добавить головоломку

1. Опишите её в файле из `server/puzzles/` объектом с хуками `init`, `setup`, `goal` и нужными из `touch`, `use`, `tick`, `hint`
   и подключите файл в `server/puzzles/index.js`. Для «один держит — другой проходит» есть готовые
   удерживаемые переключатели (`addSwitch`, `groupOn`, `anyOn`) и шлюзы (`setGate`) в `server/puzzles/util.js`.
2. Укажите её имя в `puzzles` нужного уровня в `shared/map.js`.
3. Если нужны новые объекты на карте — добавьте их вид в `client/js/world/objects.js` (`createObj`), а подсказку E — в `client/js/game/interact.js`.
4. Добавьте решатель в `tests/lib/solvers.js` — бот проверит, что уровень проходится.

## Как добавить уровень

1. Создайте `shared/levels/<имя>.js`: функция `build(map, rnd, used)` строит этажи (`gen2d`, `layerFromGrid`),
   знаковые места (`room`, `fillRect`, `placeStair`, `placeLadder`, `addBlocks`, `addLift`) и связи этажей;
   в конце — `connectFloor` на каждом этаже. Если часть карты закрыта в начале (шлюз), закройте её в `after(map)`
   и опишите шаги в `states(map)` — `verify-levels` проверит каждый шаг. Свой выход — `map.exitFixed`.
2. Подключите файл в `shared/levels/index.js` и тегом `<script>` в `client/index.html`.
3. Добавьте запись в `LEVELS` (`shared/map.js`) с `custom: '<имя>'`, стилем, существами и головоломками.

## Как добавить существо

1. Добавьте тип в конец `MOB_TYPES` и имя в `MOB_NAMES` (`shared/core.js`).
2. Опишите чувства в таблице `DEF` (`server/mobs.js`): `near`, `see`/`seeTorch`, `cone`, `runHear`, `heat`, `crawl`,
   `statue` — большинство существ не требует нового кода. Особое поведение — отдельной функцией в том же файле.
3. Модель и анимация — `makeMob` и `updateMobs` в `client/js/entities/mobs.js`.

## Сеть

- Сервер авторитетный: предметы, головоломки, существа, смерть и воскрешение, права хоста считаются только на сервере.
- Клиент отправляет позицию 20 раз в секунду, сервер рассылает снапшоты (компактный JSON) с той же частотой; клиент интерполирует других игроков и существ.
- **Античит**: сервер не принимает перемещение быстрее бега и телепорты, возвращает игрока на место
  (после телепортов сервера, лифтов и взрывов включается короткая пауза). Дальность действия (E) и подбора проверяется на сервере.
- **Переподключение**: сервер 2 минуты помнит вышедшего игрока по нику и возвращает его на то же место с теми же предметами.
- Пакет двойника (Skin Stealer) по формату неотличим от пакета игрока: клиент не получает флага «это двойник».

## Переменные окружения для отладки

| Переменная | Что делает |
|---|---|
| `START_LEVEL=4` | начать с уровня по номеру (0–10) |
| `FORCE_MAP=1` | улучшенная карта всегда выпадает (если на уровне она вообще бывает) |
| `TEST_NEAR=fuse` | игроки появляются рядом с объектом этого типа |
| `ANTICHEAT=0` | выключить проверку скорости и телепортов |
| `MODIFIERS=0` | выключить случайные модификаторы раунда |
| `ADMIN_TOKEN=...` | задать токен хоста вместо случайного |
| `RECORDS_FILE=путь` | где хранить таблицу рекордов (по умолчанию `data/records.json`) |
| `TEST_HOOKS=1` | отладочные команды для автотестов. **В игре не включать** |

Windows: `set START_LEVEL=4` и затем `node server/index.js`. Linux/macOS: `START_LEVEL=4 node server/index.js`.

## Тесты

```
npm test
```

- `tests/verify-levels.js` — 300 seed на уровень (`npm run verify`; в `npm test` — 60): выход и все объекты достижимы, нет ловушек, хэш карты в Node и в браузерной сборке совпадает, физика реально проходит рёбра графа (лестницы, провалы, стремянки, лазы, вода);
- `tests/mobs-pathing.js` — существа догоняют цель на другом этаже (лестницы, провалы, стремянки, атриумы), не застревая;
- `tests/mobs-behavior.js` — у каждого существа свои чувства: Червь слышит только бег, Фары видят только перед собой, статуи замирают под взглядом, Воспитательница спит под шкатулку, Надсмотрщик проламывает стену;
- `tests/drowner.js` — Утопленник ловит пловцов, не выходит на сушу, прячется, когда воду слили;
- `tests/skinstealer.js` — три бота: подмена не видна в пакетах (тот же формат, тот же список игроков), работают жест, кодовое слово, свет, детектор, спасение из клетки; соло-режим;
- `tests/browser-stealer.js` — то же глазами игрока в браузере: клетка, чат, освобождение, проверка жестом;
- `tests/death.js` — смерть, статистика для зрителей, метки призраков, аптечка, алтарь, поражение и рестарт уровня;
- `tests/browser-spectator.js` — в браузере: камера у глаз живого, переключение между тремя и обратно, уход наблюдаемого, воскрешение;
- `tests/director.js` — режиссёр (событие после затишья, передышка на пике), сложность (хардкор без аптечек), засуха, +1 существо вчетвером, ежедневный сид одинаков на разных серверах, рекорды на диске и по HTTP, шкафчики, реплики, роли, цвет, пасхалка;
- `tests/network.js` — античит (обычный ход принят, телепорт отклонён с поправкой), лимит игроков, переподключение с тем же местом и предметами;
- `tests/admin.js` — без токена отклоняются все команды (и поддельные), перебор токена блокируется, мусорные аргументы не роняют сервер, есть лимит частоты, с токеном все команды работают;
- `tests/browser-admin.js` — панель в браузере: гость видит только вход, хост входит по ссылке, вкладки, команды и эффекты;
- `tests/shots.js` — скриншоты лестниц, провалов, бассейнов, стремянок и лазов каждого уровня;
- `tests/smoke-server.js` — сервер отдаёт файлы, не выпускает за пределы папок, не падает от мусора и от нулевого байта в адресе, принимает игрока;
- `tests/bot-playthrough.js` — бот проходит всю кампанию через WebSocket, решая головоломки (решатели — `tests/lib/solvers.js`);
- `tests/endings.js` — вторая концовка (кресло Надсмотрщика), рестарт кампании после финала, провал по таймеру реактора;
- `tests/smoke-browser.js` — headless Chromium открывает каждый уровень, проверяет движение, фонарик, второго игрока, F3, дневник, смену пресетов качества и отсутствие ошибок JS, сохраняет скриншоты (папка из `SHOT_DIR`, по умолчанию во временной). Если Chromium не найден — тест пропускается; путь можно задать в `CHROME`.

## Технические ограничения

- Графика процедурная (модели собраны из примитивов, текстуры рисуются на canvas): это сознательный выбор — игра
  работает без интернета и без файлов ассетов. Анимации существ и игроков — процедурные (покачивание конечностей).
- Тени есть только от фонаря (пресеты «Высокое» и «Ультра»); у ламп теней нет — их сотни.
- Голосового чата нет: есть текстовый чат, метки и голосовые реплики-эмоции.
- Снапшоты по сети — компактный JSON 20 раз в секунду без дельта-сжатия: для 2–8 игроков по локальной сети этого хватает.
- Генерация карты идёт в основном потоке браузера (~0,1 с на уровень), без Web Worker.
- Цель «60 FPS на встроенной видеокарте» проверена только расчётом нагрузки (instancing, бюджет источников света,
  динамическое разрешение): автотесты рисуют программно (SwiftShader), реальный FPS смотрите по F3.
